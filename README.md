## Why ASG?

- **Native asciicast v3 support.** ASG understands v3 headers, relative event timing, resize events, embedded themes, and zstd-compressed recordings.
- **README-ready output.** The result is one self-contained SVG with no JavaScript, raster frames, or external player.
- **Sharp at any scale.** Pixel-native geometry, integer baselines, and SVG paths for terminal graphics avoid the blur and seams common in scaled terminal SVGs.
- **Run it your way.** Use the native Rust binary or the same CLI through the npm/WASI package.

## Quick start

Run once with npm:

```bash
npx --yes @kingsword/asg@latest recording.cast recording.svg --window
```

Or install either distribution:

```bash
# Native Rust binary
cargo install asg --locked

# Node.js / WASI CLI
npm install -g @kingsword/asg
```

Both install an `asg` command with the same interface:

```bash
asg recording.cast recording.svg --window
```

## Which terminal renderer should I use?

| Tool | Output | Asciicast support | Best fit |
|---|---|---|---|
| **ASG** | Animated SVG | **v3 only** | Sharp, compact terminal demos in GitHub, npm, and documentation |
| [svg-term-cli](https://github.com/marionebl/svg-term-cli) | Animated SVG | Legacy casts; no v3 parser | Existing pre-v3 svg-term workflows |
| [agg](https://github.com/asciinema/agg) | Animated GIF | v1, v2, v3 | Font-independent raster output and broad cast compatibility |
| [asciinema player](https://github.com/asciinema/asciinema-player) | Interactive HTML/JS | v3 | Playback controls and interactive web pages |

Choose ASG when the source is asciicast v3 and the destination accepts an image but not a JavaScript player. SVG text uses fonts installed on the viewer's system; choose agg when identical rasterized pixels across devices matter more than vector scaling and text sharpness.

## Inputs and compatibility

ASG accepts:

- local `.cast` and zstd-compressed `.cast.zst` files;
- stdin via `-`;
- HTTP(S) URLs;
- asciinema.org recording IDs;
- output paths or stdout via `-`.

It implements ANSI/DEC terminal behavior through asciinema's `avt` virtual terminal, including 16/256/truecolor, text attributes, alternate screen, wide Unicode, cursor visibility, and terminal resize.

> [!IMPORTANT]
> ASG intentionally rejects asciicast v1 and v2. Convert old recordings before rendering:
>
> ```bash
> asciinema convert old.cast recording-v3.cast
> ```

## Common workflows

```bash
# Local or compressed recording
asg recording.cast recording.svg
asg recording.cast.zst recording.svg

# Stream through stdin/stdout
cat recording.cast | asg - - > recording.svg

# Render directly from a URL
asg https://example.com/recording.cast recording.svg --window

# One static frame, or an animated excerpt (times are seconds)
asg recording.cast still.svg --at 4.5
asg recording.cast excerpt.svg --from 3 --to 12

# Resize, change speed, and hide the cursor
asg recording.cast demo.svg --cols 100 --rows 30 --speed 1.5 --no-cursor
```

Reproduce the README demo:

```bash
asg examples/demo.cast examples/demo.svg --window --from 0.1
```

## Rendering model and size

ASG uses a compact horizontal reel instead of duplicating complete screens:

- only visual changes become frames;
- identical states and repeated lines are reused;
- styles are shared through CSS classes;
- one discrete CSS animation moves the reel;
- box-drawing and block glyphs use crisp native SVG paths.

The demo above was generated with `--window --from 0.1`:

| Source | Output | Frames | Duration | Canvas |
|---|---:|---:|---:|---:|
| 1,744,897-byte v3 cast | 986,999-byte SVG | 146 | 29.964s | 930×544 |

The SVG is 56.56% of the cast input while remaining vector-based and self-contained. Default terminal geometry uses a 16px font, 10px cells, 22px rows, a 1:1 physical-pixel `viewBox`, and zero padding.

For parser, timeline, terminal, and renderer design details, see [the architecture document](docs/architecture.md). The Rust library entry point is `asg::generate`.
